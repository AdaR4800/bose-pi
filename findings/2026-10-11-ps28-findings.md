# Bose PS28 / Raspberry Pi 5 — Verified Findings

**Last updated:** 2026-10-11  
**Project:** `bose-pi` / Bose Lifestyle AV18/PS28, single-system setup

This document records the results directly observed during the 2026-10-11 session. It deliberately separates observed behaviour from protocol interpretations taken from Bose patents or other reverse-engineering work. It does not replace the existing sniffer or earlier repository documentation.

## 1. Current Working Architecture

- A MacBook or iPhone streams music through the already configured AirPlay receiver on the Raspberry Pi 5.
- Raspberry Pi audio output uses the INNO-MAKER Digi One HAT and its S/PDIF/TOSLINK output.
- The S/PDIF optical output was previously tested: optical light appears during playback.
- The PS28 receives S/PDIF at its J1 connector (pins 7/8 according to the project wiring notes).
- A separate UART path controls or queries the SmartSpeaker Bus. The existing passive sniffer listens on GPIO16.
- Existing sniffer command used during this session (keep unchanged):

```bash
sudo python3 /home/robert/ps28-sniffer/ps28_sniffer_v2.py
```

UART settings used by the tests: `/dev/ttyAMA0`, 4800 baud, 8N1. Existing GPIO/bus hardware and the sniffer were not modified in this session.

## 2. Confirmed End-to-End Result

**Music played successfully through the PS28.** The following sequence was used:

1. Select the S/PDIF input using `07 00 10 17`.
2. Clear mute or restore the active state using `01 00 01 00`.
3. Start playback through the already working AirPlay → Raspberry Pi → INNO-MAKER Digi One → TOSLINK path.
4. Music became audible from the Bose system. Initially, it was very loud.
5. The AirPlay volume slider was not controlling volume while Shairport Sync had `ignore_volume_control = "yes";` in `/etc/shairport-sync.conf`.
6. That setting was changed to `ignore_volume_control = "no";` and Shairport Sync was restarted. The user subsequently confirmed that AirPlay volume control works adequately for now; fine-tuning is deferred.
7. A speaker-mode command `05 00 05 00` was sent, after which the user reported that sound was coming from all speakers. The precise mapping and semantics of this value should remain tagged as an observed working result until checked against the exact PS28 documentation.
8. A spatial/circling music test from Apple Music sounded “SUPER” to the user.

### AirPlay Troubleshooting Note

A later period with no sound was initially suspected to be a PS28 state or heartbeat issue. The user identified the actual cause: AirPlay playback on the MacBook had hung after the Restart of Shairport Sync.

## 3. Commands and Observed Behaviour

All four-byte frames below have an XOR checksum in the final byte (XOR of the first three bytes).

| Purpose / test | Transmitted frame | Observed result | Evidence status |
|---|---|---|---|
| Activate / restore previous state, clear mute | `01 00 01 00` | Music became immediately audible, without restarting AirPlay | **Confirmed by listening test** |
| Normal shutdown | `01 00 80 81` | Music stopped abruptly while AirPlay continued running | **Confirmed by listening test** |
| Select primary S/PDIF input | `07 00 10 17` | Subsequent input query returned value `10`; audio was audible after unmute | **Working in the tested setup** |
| Query ON/OFF state | `0B 00 00 0B` | Responses varied by state | **Repeatedly observed** |
| Query audio input | `0B 00 05 0E` | Response `00 0C 00 10 1C` | **Observed; interpretation based on correlation** |
| Set speaker mode | `05 00 05 00` | User subsequently reported audio from all speakers | **Observed working result; exact mode label should be verified** |

### State-Query Response Captures

| Context | Response to `0B 00 00 0B` |
|---|---|
| Earlier capture | `00 0C 00 F1 FD` |
| After sending `01 00 00 01` | `00 0C 00 00 0C` |
| After sending `01 00 80 81` | `00 0C 00 F0 FC` |
| Later, after time had passed | `00 0C 00 00 0C` |

The response checksums validate under XOR. For example:

`00 XOR 0C XOR 00 XOR F0 = FC`

The correlation between the state byte and the tested commands is strong, but do not overstate the semantics of the complete response format without exact-model evidence.

### Input Query

- Query: `0B 00 05 0E`
- Response: `00 0C 00 10 1C`
- XOR check: `00 XOR 0C XOR 00 XOR 10 = 1C`
- Interpretation: response data byte `10` matches the value used to select the primary S/PDIF input. This is a correlation observed on the PS28; exact response-field definitions remain to be documented.

### RX After Control Commands

For commands `01 00 00 01`, `01 00 80 81`, and `01 00 01 00`, the passive GPIO16 sniffer showed the four transmitted bytes followed by an additional `00` after a short gap.

Treat the trailing `00` as a repeatable bus observation. Its origin and direction have not been independently isolated; do not claim its exact semantics.

## 4. Shairport Sync Volume Setting

The user inspected `/etc/shairport-sync.conf` and observed:

```conf
output_backend = "alsa";
ignore_volume_control = "yes";
```

The second line was changed to:

```conf
ignore_volume_control = "no";
```

Shairport Sync was restarted with:

```bash
sudo systemctl restart shairport-sync
systemctl is-active shairport-sync
```

`amixer -c 1 scontrols` only showed `Simple mixer control 'Tx Source',0`, i.e. no normal hardware volume mixer was exposed for the Digi One. The intended volume control is therefore Shairport Sync's digital volume control.

The user confirmed that AirPlay volume control works adequately after this adjustment; detailed calibration is deferred.

## 5. Important Command Examples

Send one SmartSpeaker frame (example: select S/PDIF input):

```bash
sudo python3 - <<'PY'
import serial
frame = bytes.fromhex("07 00 10 17")
with serial.Serial(
    "/dev/ttyAMA0", baudrate=4800, bytesize=8, parity="N", stopbits=1,
    timeout=0, write_timeout=1, xonxoff=False, rtscts=False, dsrdtr=False,
) as ser:
    ser.write(frame)
    ser.flush()
    print("Sent:", frame.hex(" ").upper())
PY
```

Status query frame: `0B 00 00 0B`  
Input query frame: `0B 00 05 0E`

Do not run the sniffer and a second program that concurrently owns `/dev/ttyAMA0` unless the test is specifically designed for that. The existing sniffer is a GPIO16 passive listener; the sending script writes UART0.

## 6. Sources and Confidence Labels

Use the following labels in future documentation:

- **OBSERVED_PS28** — directly observed on this PS28, including audible results and raw capture.
- **PATENT** — documented in Bose patent US8214447B2, *Managing an audio network*. Patent behaviour is not automatically guaranteed to match this PS28 firmware.
- **SERVICE_MANUAL** — exact-model service documentation or schematic.
- **KENNERACT_3_2_1** — reverse-engineering notes for a Bose 3·2·1 GS Series III, not the PS28; useful for comparison only.
- **INFERENCE** — supported by correlation but not yet independently established.
- **UNKNOWN** — unresolved.

Relevant references:

- Bose patent US8214447B2: https://patents.google.com/patent/US8214447B2/en
- Kenneract SmartSpeaker protocol notes (3·2·1 GS Series III, not exact PS28): https://github.com/Kenneract/Bose-Reverse-Engineering/blob/main/SmartSpeakerProtocol.md
- Exact PS18/PS28/PS48 service documentation and schematic SD267086 are referenced in the wider project notes; retain the source document and page when adding further claims.

Kenneract's work is an important reference for this investigation. Its findings should be credited and linked, while clearly distinguishing observations from the 3·2·1 GS Series III from measurements made on the Bose AV18/PS28 installation.

## 8. Short Operational Sequence That Worked

1. Ensure AirPlay playback is actually running on the MacBook or iPhone.
2. Send `07 00 10 17` to select the primary S/PDIF input.
3. Send `01 00 01 00` to restore or unmute; music became immediately audible.
4. Optional: send `05 00 05 00`; the user reported that all speakers became active.
5. To stop Bose output while leaving AirPlay running, send `01 00 80 81`; music stopped immediately.
6. To restore audio without restarting AirPlay, send `01 00 01 00`; music resumed immediately.
7. Query state with `0B 00 00 0B` and capture through the existing sniffer.
